调研日期：2026-07-16

## 1. 调研方法

本轮不再依赖搜索引擎的 `site:oshwhub.com` 索引，而是直接访问嘉立创开源硬件平台。

- Chrome Headless 无法在合理时间内完成搜索页渲染。
- 安装并使用 Lightpanda `1.0.0-nightly.8075+581eafcf` 后，可以获得完整页面 HTML。
- 从搜索页 JavaScript 定位到 `/api/search/data` 和 `/api/project/{uuid}` 接口。
- 使用“宏键盘”“RP2040 键盘”“旋钮 键盘”“小键盘 RGB”“QMK RP2040”等关键词检索。
- 对候选项目进一步核查项目说明、附件、固件、结构文件和平台标记的许可证。

这说明平台并非无法访问；上一轮只是没有使用正确的动态页面/API 调研方法。

## 3. 最值得深入研究的项目

### 3.1 ZERO-PAD：首版工程原型参考

ZERO-PAD 与我们的 MVP 最接近：

- 微雪 RP2040-Zero 主控。
- QMK 固件，同时提供 VIA/Vial 改键路线。
- 10 个直连按键、2 个 EC11、WS2812、I²C 屏幕和反馈器件接口。
- 大板与功能小板分离，可以快速更换双旋钮、RGB、屏幕、蜂鸣器、振动马达和不同轴体模块。
- 附件包含 BOM、固件、部分图纸源文件、3MF 外壳和组装说明。

可借鉴的是模块边界和验证顺序，而不是直接复制 PCB：

1. 用 RP2040-Zero 降低第一块 PCB 的主控风险。
2. 将核心键盘板与实验性控件分离。
3. 首轮按键数量较少时使用 GPIO 直连，避免矩阵和二极管增加调试变量。
4. 预留独立 RGB、I²C 和反馈器件接口。

局限：项目为 `CC BY-NC-SA 4.0`，作者明确标注禁止商用。我们可以研究其公开方法，但商业产品必须自行重新设计原理图、PCB、结构和固件集成。

### 3.2 3Plus V2：桌面状态终端参考

3Plus V2 的产品形态不是传统键盘，而是三个带屏幕的实体按键。它对 Agent Console 很有启发：

- 每个物理槽位可以显示不同任务的信息，而不只是固定 RGB 颜色。
- 上位机可以下发天气、股票和电脑状态，证明“桌面 Bridge → USB/Wi-Fi 设备状态显示”路线可行。
- V2 专门针对低成本、少 PCB、易焊接和 OLED 老化问题进行了工程优化。
- 附件包含 BOM、Gerber、固件、源码包、亚克力面板源文件和 STL。

不建议第一版采用三个 TFT：显示屏会提高 BOM、功耗、固件复杂度、装配时间和结构公差风险。可以将它作为后续高级版参考。

### 3.3 IcePad：透明交互和桌面摆件参考

IcePad 使用 ESP32-S3、透明磁悬浮按键、霍尔传感器、LCD 和 RGB。它证明透明按键与状态图标具有很强的视觉吸引力，但也暴露出工程成本：

- 磁铁极性、霍尔阈值和机械行程需要一致性控制。
- 透明打印件的雾度、层纹和后处理直接影响成品观感。
- 屏幕型号和外壳尺寸形成供应链绑定。
- 复杂结构不适合作为低成本首版。

适合借鉴视觉语言，不适合直接作为首版硬件基础。

### 3.4 AFpad-AT：极低成本 QMK/Vial 参考

AFpad-AT 使用低价 AT32F413，集成 14 键、双旋钮、屏幕和 USB Hub，并支持网页端改键。对成本工程很有价值：

- 主控价格可以低于常见 RP2040 模块。
- QMK/Vial 能覆盖大部分传统宏键盘功能。
- USB Hub 可减少桌面接口占用。

但首版仍建议使用 RP2040：生态更成熟、TinyUSB/串口复合设备更容易实现，且我们的核心不是把 MCU 单价压到最低。USB Hub 也会增加布局、EMI 和兼容性风险。

### 3.5 CH552G 小键盘：成本下限参考

该项目记录的整机成本约为十几元级，证明普通 HID 宏键盘本身几乎没有硬件门槛。不过作者也明确记录了：

- 原始按键扫描和消抖实现难以可靠处理组合键。
- USB-C 版本需要正确配置 CC 下拉电阻。
- 自动生成的 3D 外壳存在装配过紧问题。

因此它适合建立成本下限和常见失败案例，不适合作为多 Agent 产品的软件基础。

## 4. 对我们硬件架构的直接启示

### 首块 PCB

建议吸收 ZERO-PAD 的低风险思路，但做独立设计：

- RP2040-Zero 插接或邮票孔模块。
- 8 个直连按键，不使用键盘矩阵。
- 2 个 EC11 编码器。
- 8 至 12 颗 SK6812 MINI-E。
- 一个独立扩展连接器，提供 `3V3`、`5V`、`GND`、`I2C`、`SPI` 和若干 GPIO。
- USB 由 RP2040-Zero 模块承担，第一版主板暂不重复设计 USB PHY 周边。

### 第二版 PCB

完成协议和交互验证后再考虑：

- 板载 RP2040、Flash、晶振、USB-C 和 ESD。
- 将按键改为矩阵，以支持更多 Agent 槽位。
- 增加可选小屏模块，而不是每个键都绑定显示屏。
- 设计测试点、SWD、产测固件和治具接口。

### 结构

嘉立创项目普遍证明以下结构更适合低成本小批量：

- FR4 底板 + 定位板 + 铜柱。
- 激光切割亚克力夹层。
- 3D 打印底壳 + 标准键帽。

第一版不将透明一体式外壳作为前置条件。透明打印、磁悬浮按键和定制键帽应作为独立的工业设计研发课题，在交互与电子架构验证后推进。

## 5. 许可证结论

嘉立创平台上“可以打开工程并免费打样”不代表“可以商业销售”。本轮最相关项目中，大多数使用带 `NC` 的 Creative Commons 许可证：

- `CC BY-NC-SA`：允许学习、分享和非商业改编，不允许未经许可的商业使用。
- `CC BY-SA`：允许商业使用，但衍生作品必须署名并按相同许可证分享。
- `Public Domain`：平台标记较宽松，但仍需检查附件源码中引用的第三方代码和设计。

工程规则：

1. 不复制 `NC` 项目的原理图、PCB 布局、外壳或可识别的结构设计进入商业产品。
2. 仅将其作为需求、模块划分、器件和失败案例的研究输入。
3. 所有正式硬件从独立需求重新设计，并保留设计记录和审图记录。
4. 对可能复用的代码逐文件确认许可证，不能以平台项目总许可证替代源码许可证审查。
5. 如果某个设计确实值得直接授权，单独联系作者取得书面商业许可。

## 6. 下一轮下载与审查清单

在进入原理图设计前，建议对以下项目下载工程并进行离线审查：

1. ZERO-PAD：检查 RP2040-Zero 引脚规划、RGB 供电、模块连接器和 QMK 配置。
2. 3Plus V2：检查 Bridge/设备通信、屏幕刷新和附件 BOM 组织方式。
3. CH552G 小键盘：提取低成本 BOM，并记录 USB、消抖和结构失败点。
4. RP2040 QMK 主控板：仅用于审查最小系统和 USB 设计，不直接复用。
5. RP2040 数字键盘：确认 `CC BY-SA` 对工程文件和固件的具体覆盖范围。

下载的第三方工程不应直接提交到本仓库。建议存入独立的、被 Git 忽略的 `references/vendor/` 工作目录，并在审查文档中记录文件哈希、下载日期和来源 URL。
